# verify-ssti：服务端模板注入（SSTI）验证

`vuln_type = ssti` 类 Confirmed 的**唯一合法产出门径**（职责隔离：发现类 skill 只能产
Signal/Hypothesis）。执行由编排器 `run_verify_phase()` 确定性驱动；唯一的 LLM 调用
是收尾的 **Verifier 终审**（T2，独立 agent + 输入边界）。

## 本 skill 确认的是什么（**先划清边界**）

**唯一认可确认手段 = 同一语法下两个不同的乘法表达式都被服务端算出了正确乘积**，
且**基线响应里没有这两个数字**。这是**差分求值**的二值事实：号码是模板引擎算出来的，
不是页面里本来就有的、也不是取值被拼接出来的。

**不作证据的东西**（一律不看）：

| 观测 | 为什么不是证据 |
|---|---|
| 响应里出现 `{{ }}` / `${ }` / `<%= %>` 字面量 | 只证明**参数被回显**，没证明被求值（这正是形对照） |
| 模板报错文本（`TemplateSyntaxError` 等） | 说明参数进了模板上下文，但没说它被**执行**了 |
| 状态码 / 响应长度 / 耗时 | 与求值无关 |

> 这条与 sqlmap 的"报错型注入"刻意不同：**报错不是证据**。报错只证明参数到了某个
> 解析器手里，乘积才证明它被算了一遍。

## 探针（固定、无副作用、只 GET）

| 语法（引擎族） | 探针 A | 探针 B | 畸形对照 |
|---|---|---|---|
| `{{...}}`（Jinja2 / Twig / Django / Nunjucks） | `{{191*191}}` | `{{191*192}}` | `{{191*191}` |
| `${...}`（EL / FreeMarker / JSP） | `${191*191}` | `${191*192}` | `${191*191` |
| `<%= ... %>`（ERB / EJS） | `<%= 191*191 %>` | `<%= 191*192 %>` | `<%= 191*191 %` |

- 乘积是 **5 位数**（36481 / 36672）而不是 49：页面里本来就有 49 的概率高得离谱，
  有 36481 的概率极低。匹配用**数字边界**（前后不紧邻数字），否则 `136481` 会假命中。
- **一类语法命中即可**，不必三类全中。

## 三道对照（缺一不可）

1. **基线**：`finding.asset` 原样响应不含这两个乘积 —— 没有它，"出现乘积"可能只是
   页面本来就有的数字（反事实不可测）。
2. **两个乘积**：同一语法换操作数，**两个**乘积都要出现。只中一个说明不了求值
   （可能是静态文本、也可能是取值被拼接进别的地方）。
3. **畸形模板对照**：少一个右括号的探针**不得**算出乘积。它挡的是「strip 掉非数字后
   照样算乘法」这类端点 —— 那边点三个探针全中，但**判不了**。

## 判定表（宁漏勿滥）

| 观测 | 结论 |
|---|---|
| 基线干净 ∧ 某语法两个乘积都出现 ∧ 该语法畸形对照不出现乘积 | **confirmed** → REPRODUCED → 证据门 → Verifier |
| 全部探针无错、且任何响应都没出现乘积（含"回显字面量但不求值"） | **rejected**（真阴性，actor=verify-ssti） |
| 只中一个乘积 / 两个乘积分属不同语法 / 任一请求出错 / **基线本身含乘积** / **畸形对照也出乘积** | **blocked**（覆盖不全，绝不驳回） |

## 预算与顺序

每候选 **≤8 次只读 GET**，排程是确定性的：

```
1  baseline
2-3  语法1：探针 A、探针 B ──两个都中──> 4  语法1 畸形对照  ⇒ 4 次结束
     └未命中→ 4-5 语法2 ──命中──> 6 畸形对照
          └未命中→ 6-7 语法3 ──命中──> 8 畸形对照
全部未命中 → 7 次 → rejected
```

## 诚实边界（**本 skill 明确不做**）

1. **不覆盖盲注型 SSTI**：求值结果不回显到响应里（如只进日志、只进生成的文件），
   本判据结构上看不见 —— 那需要带外观测手段，未做；
2. **不做模板指纹识别**：不区分 Jinja2 与 Twig、不产引擎专用的 RCE 链、不读文件、
   不反弹 shell —— 探针只有一个乘法表达式；
3. **语法覆盖有限**：只试 `{{ }}`、`${ }`、`<%= %>` 三族。其它语法（如
   `{%...%}` 语句块、`#{...}`）不在本轮范围；漏试即漏报（保守方向）；
4. **只覆盖 GET query 参数**：POST 表单/JSON body 型候选的 SSTI 验证未实现
   （候选缺 `param` 或证据类是 `crawl-form` 时一律 `verify_blocked`，不凭空造 URL）；
5. **求值结果被截断时匹配不上**：只回显前几位数字的端点会判 `rejected`
   （宁漏勿滥的保守方向，不猜）。

## 与其它类型的关系

判据与 sqli 的布尔/时间差分**同构但不同源**：SSTI 的产物是模板引擎算出来的**值**，
不需要数据库、不需要错误回显、不需要时间差异。故 method
（`template-eval-confirmed`）与具名证据标签（`template-evaluation`）都与其余六类
**互不染指**，证据门因此不会把别的类型的结论当成 SSTI 的证据。
